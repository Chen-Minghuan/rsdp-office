# Spatial 附件 C：确认、版本与失效规则 V1.0

2026-10-15 用户最新要求优先：实际工作台不再要求逐个或全部确认空间，识别/重叠等复核提示不阻止排版，仅保留可靠比例和可计算轮廓条件。下述逐空间/整体空间确认是旧目标 API 的历史设计，不再作为进入家具排版的产品条件；当前实现见 [FLOW-002](../tasks/FLOW-002-advisory-space-review.md)。

更新日期：2026-10-14。目标规则，尚未实现。
关联：[数据协议](../../Spatial_Scene_数据协议规范_V1.0.md)、[几何规则](geometry-rules.md)、[接口/存储](api-storage-contract.md)。

## 1. 版本职责

| 版本 | 作用 |
| --- | --- |
| scene.revision | 每次成功业务变更的乐观锁；确认也产生新修订，幂等重放不新增 |
| geometryRevision | 单空间轮廓、孔洞及矩形 frame 的版本；由服务器按语义 diff 增加 |
| requirementRevision | 单空间确认条件版本，含几何、用途、父子关系、约束、质量处理和纳入状态 |
| calibrationRevision | 全场景物理解释版本 |
| scopeRevision | 纳入设计空间集合与父子结构版本，整体确认的依据 |
| metadataRevision | 名称、普通标注等不影响设计约束的元信息版本 |
| geometryPolicyVersion | 几何边界与校验策略版本，固定为 GEOM-P1-1 |

客户端不设置派生版本，后端在一个事务中计算 diff、相关问题、版本与失效状态。
`confirmedRevision` 指空间确认时的 requirementRevision，另记录 confirmedGeometryRevision 和 calibrationRevision，避免只按轮廓版本漏掉约束变化。
确认快照还保存来源版本、约束/质量处理、策略版本和实际被确认的场景修订。

## 2. 操作—版本—失效范围

以下影响空间指包括变更对象的归属空间、受影响父子空间、明确邻接关系双方以及冲突出现/消失的另一方。
后端以旧/新关系和旧/新几何的并集计算影响集合，不能只看修改后的归属；不相关房间不失效。
所有业务变更增加 scene.revision；表中另列其他版本。没有实际差异的草稿保存只返回原修订与幂等回执。

| 操作 | 增加的其他版本 | 空间确认 | 整体确认及下游 |
| --- | --- | --- | --- |
| 移动、拖边/顶点、尺寸/孔洞改变 | 本空间 geometryRevision；影响空间 requirementRevision | 本空间与关系/冲突影响空间失效 | 整体失效；相关布局待核验，推荐/方案/渲染过期 |
| 应用或重新校准 | calibrationRevision；全部空间 geometryRevision/requirementRevision | 所有依赖空间失效 | 整体及全部依赖下游失效 |
| 排除空间 | scopeRevision；本空间及关系影响空间 requirementRevision | 本空间状态 EXCLUDED；父/子与相关冲突空间失效 | 整体失效；该空间旧布局保留为排除历史 |
| 恢复空间 | scopeRevision；本空间及关系影响空间 requirementRevision | 本空间恢复 UNCONFIRMED，旧确认不可自动恢复 | 整体失效；旧布局须重新核验 |
| 新建或删除人工空间 | scopeRevision；受影响空间 requirementRevision | 新空间未确认；删除空间为历史墓碑 | 整体失效；引用保留并标待处理 |
| 更换 parentSpaceId/kind | scopeRevision；旧/新父空间、子空间及关系双方 requirementRevision | 所有影响空间失效 | 整体失效；归属和布局需求待核验 |
| 新增/修改/删除柱、禁放区 | 旧/新归属与占地相交空间 requirementRevision | 所有影响空间失效；净面积依策略重算 | 整体失效；相关布局/商品匹配待核验 |
| 墙、门窗或已知共边关系变化 | 关系双方及相关空间 requirementRevision | 所有影响空间失效 | 整体失效；通行、开口与布局重新核验 |
| 用途 category 或业务约束变化 | 本空间及依赖空间 requirementRevision | 失效，即使轮廓没变 | 整体失效；家具需求/推荐重新匹配 |
| 仅名称更改 | 本空间 metadataRevision | 保留 | 保留；旧快照名称不改，界面区分历史名称 |
| 质量问题处理/撤销处理、图层可用性变化 | 问题涉及空间 requirementRevision | 受影响确认失效，重新核验后可再确认 | 整体失效；未知约束相关下游待核验 |
| boundaryBasis、来源版本替换 | 相关空间 geometryRevision（几何有变时）/requirementRevision | 受影响确认失效 | 整体及相关下游失效 |
| 几何策略版本改变 | 受影响空间 requirementRevision | 重新核验，不沿用旧策略确认 | 整体失效 |
| 纯便签/颜色变化 | metadataRevision | 保留 | 保留；若便签被转为业务约束，按约束变化处理 |
| 相机、底图透明度/显示开关 | 不增加上述业务版本 | 保留 | 保留；显示设置单独保存 |
| 显式应用底图配准变换 | calibrationRevision 及关联几何/需求版本 | 按校准失效 | 按校准失效；不能作为纯显示操作 |

排除父空间时，其纳入设计的子空间不能保留无效父引用：同一草稿批次须显式排除子空间或更换父空间，否则产生阻止整体确认的问题。
修改名称不改变确认条件；改用途改变排版需求，因此不能与名称修改采用同一失效规则。
撤销/重做按逆向业务变更执行本表；历史确认仅保留审计，撤销后不自动标成已确认。

## 3. 逐空间确认

`scope=SPACES`，请求包含非空空间 ID 和当前 geometryRevision、requirementRevision；必须匹配校准与 scene baseRevision。
后端检查：目标纳入设计、比例可靠、边界依据已确定、合法几何、必要质量问题已处理，以及相关父子包含、邻接/重叠、门窗和障碍问题。
只核验目标及其关联冲突，不要求其他独立房间已完成或已确认。

例：A 已校准且有效，独立 B 未命名且待修复，A 可确认；若 A 与 B 重叠，则 A 不能确认，即使 B 本次不在目标列表中。
同次确认多个空间采用全有或全无语义；任一目标不满足则 422，其他目标不新建确认。
已经按同一条件确认的空间不重复生成空间快照；不同 clientChangeId 的相同确认请求可返回原空间快照，场景无实际变化则不增加修订。

## 4. 整体确认

`scope=SCENE`：纳入设计的空间至少一个，纳入集合/父子结构明确，全部空间已经逐一按当前条件确认，全部关联冲突通过校验。
整体操作不替用户自动确认未确认空间；返回各缺失/失效空间及问题。
生成不可变整体快照，记录 scopeRevision、每个空间确认 ID/需求版本、校准、策略、来源页和场景修订。
只有整体确认有效时，后续家具排版才使用其输入；逐空间确认可先完成，不等于已允许进入完整排版阶段。

## 5. 保存与确认的顺序

确认只针对服务器已保存修订。客户端存在本地未提交编辑时，先等待保存成功，再以服务器版本提交确认。
确认成功后若本地已出现新改动，显示已确认历史修订、当前草稿未确认，并按新变更保存使相关确认失效；不得给新草稿套用旧确认。
网络重试、队列和回包处理见 [附件 B](api-storage-contract.md)，确认失效、快照与回执在同一数据库事务提交。
