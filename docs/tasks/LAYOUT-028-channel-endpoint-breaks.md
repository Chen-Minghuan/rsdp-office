## 目标与验收

触发：用户需要"通道不到头"的真实画法（如通道只从二排通到后墙、或两端不到墙）。
结果：通道支持沿走向的起止偏移（startMm/endMm，世界毫米），不再强制贯通全跨；渲染、排版切段、确认校验同步；同时评估横向通道是否对称支持「仅从二排起」（首列不断开），结论与理由记入任务卡。
范围：通道数据模型扩展（向后兼容，缺省贯通）；弧形/斜向不属此卡。

## 定稿语义（2026-10-23）

- 数据模型：`LayoutChannel` 新增 `startMm?` / `endMm?`（世界毫米：纵向为 y、横向为 x），**缺省贯通**——旧数据无字段行为不变，无需迁移。
- 有效走向范围 = 包围盒 ∩ [startMm, endMm] ∩ （「仅从二排起」的首排深度之后）；startMm≥endMm 时无有效禁放带（`channelRects` 跳过、服务端同样跳过），`validateChannels` 给出"通道起点必须小于终点"。
- **「仅从二排起」保留独立字段，不迁移为 startMm**：它的断开位置是应用排版时按当前家具 `layoutSettings.firstBlockDepthMm` 动态得出的，迁移成静态数值会把语义冻结在一次排版结果上；两者按交集叠加。
- **横向不做对称「仅从二排起」布尔**：排版引擎的"首个对组/首排深度"概念只存在于排轴（纵深方向），列轴没有对应语义，布尔字段无法映射；横向首列留断用 startMm/endMm 数值表达已覆盖该诉求。
- 排版切段边界：`axisSegments` 与分段网格仍按**未留断的全轴禁放带**切列/分排（与 LAYOUT-027 裁剪同一取舍——桌列不跨通道线）；端点留断影响渲染、压占确认与避障阻挡。让自动排版"绕过通道端点"需要二维装箱模型，超出本卡范围，如实记录。
- 端点编辑入口：画布浮动编辑卡与排版面板通道卡片均新增「起点/终点 mm」（相对包围盒显示，空=贯通）；走向端点不提供拖柄（拖柄仍是宽度轴两端），留作后续交互增强。

## 实现

- 前端：`channelRects` 按上述交集语义收窄走向范围（再经包围盒钳制与多边形裁剪）；`validateChannels` 校验端点有限性与先后关系。
- 后端：`OfficeLayoutValidationPolicy.channelBands` 同步 startMm/endMm 与 fromSecondRow 的交集语义（`axisFrom/axisTo`），非法（起≥止）跳过与前端一致。
- UI：编辑卡/侧栏通道卡片新输入均走 `updateChannel`/`updateSelectedChannel` → `store.updateZoneChannels` 同一失效与撤销链路。
