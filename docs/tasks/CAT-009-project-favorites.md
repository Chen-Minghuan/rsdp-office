# CAT-009 项目商品收藏与统一收藏中心

## 目标与范围

商品库采用方案 C：商品图片默认隐藏操作按钮，鼠标悬停、键盘聚焦时显示右上角「＋ / 爱心」，触屏设备直接显示。两个按钮打开同一个「收藏商品」弹窗，分别落在「项目收藏 / 个人收藏」页签。

- 项目收藏页签展示当前用户全部可访问项目，当前项目排第一并默认选中；用户可选择保存到其他项目，已选项目仍可取消收藏。
- 每个项目收藏仍按 `(project_id, user_id, rspu_id)` 隔离：user1 在项目 A 的收藏，user1 切换到项目 B 后不可见，user2 在项目 A 也不可见。
- 个人收藏继续绑定当前用户，默认收藏夹、自建分组、多选和跨项目爱心状态保持不变。
- 无当前项目时「＋」禁用；当前项目只作为默认排序和初始选择，不再锁定保存目标，项目收藏不共享给项目内其他成员。
- 本轮不包含项目自定义收藏夹、空间分组、独立收藏管理页或项目共享收藏。

## 数据与接口

现有 `office_favorite_folder`、`office_favorite_item` 不变。新增 `office_project_favorite_item(project_id/user_id/rspu_id/created_at)`，联合主键防止同一成员在同一项目重复收藏；项目和用户删除时级联清理，商品仍为 RSDP `rspu_id` 弱关联。迁移为 `20261123_office_project_favorites.sql`，同时登记到 `schema.sql` 和启动迁移。

接口：

- `GET /api/v1/office/projects/{projectId}/favorites/product-ids`：当前成员在当前项目已收藏商品 ID。
- `GET /api/v1/office/projects/{projectId}/favorites/{rspuId}`：当前商品是否已选。
- `PUT /api/v1/office/projects/{projectId}/favorites/{rspuId}`：提交 `{ selected }`，幂等新增或移除。

用户 ID 只取服务端会话；每次读取和保存均通过 `OfficeProjectAccessService.requireMember` 核验项目访问权，商品读写前核验商品可见性。前端不能传入其他用户 ID。

## 前端实现

- `products/index.vue` 分别维护个人与项目商品 ID 集合；项目切换立即使旧请求失效并清空旧项目状态，个人集合不刷新。项目保存回传项目 ID，避免旧项目结果写入新项目。保存成功后重新核验完整 ID 列表，不让被作废的进行中响应丢失其他收藏。
- 商品库在原地切换项目时不按楼层重挂载，也不被楼层加载占位替换；其他项目/画布页面继续沿用原楼层隔离和加载行为。
- `FavoriteFolderDialog.vue` 承载统一弹窗：项目页签以单选列表展示全部可访问项目，当前项目优先且默认选中；切换目标项目会立即高亮目标行，重新读取该项目商品状态，并以行内加载图标、固定高度状态区和「读取中…」按钮提供稳定反馈，保存使用被选项目 ID。个人页签沿用原有文件夹逻辑。两个页签独立加载和保存，切换页签不自动提交。保存使用商品、项目和勾选快照，响应发布与关闭前再次校验会话。
- 加载失败禁止以空选择保存；保存失败保留弹窗和旧按钮状态；会话编号和商品/项目键防止迟到响应覆盖新商品。
- `useOfficeApi.ts` 和 `favorites.ts` 增加项目收藏请求与返回类型。
