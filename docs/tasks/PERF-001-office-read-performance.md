# PERF-001 Office 读取性能

2026-11-24 完成项目列表和预算拆分、商品详情去重、选品目录回源合并。沿用 Office 默认 23 张表。

## 实现

- 浏览器先读取项目、楼层、负责人及成员，项目列表挂载后异步读取预算。预算等待或失败时仍可打开项目。保留原项目列表接口默认附带预算的行为，用 `includeBudget=false` 选择轻量响应。
- 预算接口按当前会话重新计算可见项目，按楼层选品数量与当前可见商品的零售价计算，保留已完备、待补价和不可用状态。已确认报价、报价权限与导出仍由原接口处理。
- 直达商品详情时，页面挂载不受当前楼层初始选择影响。项目列表、商品等页面无需加载画布、购物车或设计用选品目录。进入图纸、画布和方案时按当前楼层加载。
- 预算和选品目录按共享库、已绑定工厂两种目录范围使用各自的 30 秒缓存。同一实例、同一范围内只执行一轮冷刷新，无目录权限时直接返回空。刷新失败可在后续请求重试。

## 前后实测

使用同一份本机 Office 存量副本、真实 RSDP 测试目录的 185 个商品和同一经销商主号下的 3 个项目。端到端接口耗时包含 HTTP，SQL 使用隔离 PostgreSQL 的 `pg_stat_statements`，浏览器以项目列表或商品规格可见计时。冷样本为目录缓存失效后的首次读取，热接口为 5–6 次的中位数，页面热样本报告范围。

| 读取场景 | 改造前 | 改造后 |
| --- | ---: | ---: |
| 项目列表接口，冷目录 | 2338.96 ms | 9.23 ms |
| 项目列表接口，热目录 | 10.75 ms | 7.49 ms |
| 工作台项目列表可见，冷目录 | 2335–2418 ms | 203 ms |
| 工作台项目列表可见，热目录 | 104–117 ms | 106–114 ms |
| 预算接口，冷目录 | 随列表返回 | 2037 ms，与两次目录请求并发 |
| 预算接口，热目录 | 随列表返回 | 10.13 ms |
| 并发冷读预算与目录，两条都返回 | 3839 ms | 1959 ms |
| 并发冷读预算与目录，RSDP 请求数 | 464 次 | 232 次 |
| 选品目录接口，热目录 | 4.90 ms | 4.34 ms |
| 直达商品详情 Office 请求数 | 2 次 | 1 次 |
| 直达商品详情 RSDP 读取（含图片） | 8 次 | 5 次 |
| 直达商品详情规格可见，3 次中位数 | 311 ms | 315 ms |

项目列表冷读累计 SQL 执行时间为改造前 0.17 ms、改造后 0.20 ms，RSDP 调用由 232 次降为零。双请求并发对照各执行一次，改造前预算随列表返回，改造后读取预算接口。另一次冷目录测试并发了预算和两次选品目录请求，三条接口都成功，整体只回源一轮，共 1 次商品列表、185 次变体、46 次详情。工作台冷样本中预算约在导航后 2428 ms 返回。改造后商品详情三次样本为 309、315、812 ms，去重减少负载，页面中位耗时接近原值。

本阶段结束时，历史选品行可只存变体 ID，冷预算仍需读取一次完整目录。后续批量查价和商品库分页见 [PERF-002](PERF-002-batch-prices-catalog-pagination.md)。

## 验证

- 真实 Office API 和隔离 PostgreSQL 验证经销商主号预算与旧接口逐项一致、只读成员仅能访问获授项目的预算/画布/购物车、同会话撤权立即生效、同工作区成员无法读取未授权的报价或改权限、跨工作区隔离、关闭共享库且无工厂绑定时目录为空且不回源。系统管理员账号仅保留存量明确授予的历史项目访问。
- 实际读取共享目录、商品详情、画布、选品清单、图纸识别结果、收藏、工作区账号、本地商品列表和报价试算均成功。真实浏览器验证直达商品只请求一次详情，并打开收藏、共享商品库和报价试算。Java 350 项通过，含 PostgreSQL 测试，前端生产构建通过。空库按启动顺序应用 21 个 SQL 文件后确认有 23 张表，存量副本另含两张手动扩展表。
- 工作流、项目楼层、工作区隔离、报价、账号中心、收藏、图纸交接、识别进度、空间核对和冒烟均通过浏览器模拟 API 验证。实测环境未发布到生产。
