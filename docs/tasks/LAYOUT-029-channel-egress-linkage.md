## 入口数据可用性盘点（2026-10-23，任务前置步骤）

| 数据源 | 门/入口数据 | 结论 |
| --- | --- | --- |
| 视觉识别（QwenVisionClient） | 只输出空间轮廓；提示词要求"门洞沿墙方向连接"（轮廓在门处不截断），不产出门位置 | 不可用 |
| CAD 解析服务 | 无 door/opening 概念 | 不可用 |
| `openings` 契约层 | 前后端类型均存在但恒为空数组（layerAvailability 仅在人工标注门洞后标 PARTIAL） | 空壳 |
| DOOR_CLEARANCE 障碍（门洞净空扇形） | 人工标注；`outer[0]`=铰链点（贴墙≈门位），扇形半径≈门宽 | 可用但依赖人工标注 |

结论：识别数据中没有入口，只能以人工标注的门洞净空作为入口代理；未标注的空间不做衔接校验，只提示"未核验"。

## 定稿语义（2026-10-23）

- **严格级别：提示，不拦截**（用户定稿）。理由：门数据靠人工标注可能缺失，拒绝会误伤未标注空间；通道数值是策略非规范（LAYOUT-023 先例）；saveCanvas 为同步成功/失败接口，提示级无需改契约。
- **前后端一致性偏差**：提示级校验不进入后端 `OfficeLayoutValidationPolicy`（该挂点只有拒绝语义，接口无 warnings 通道，改契约超出本卡范围）；提示全部由前端在排版面板确认前给出。与 021/022 的"前后端同语义"不同，如实记录。
- **规则 1 通道衔接入口**：通道带走向两端头（028 端点留断后的实际跨度、027 裁剪分段的包围范围）至少一端在 `DOOR_LINK_BUFFER_MM`（600mm，策略值）缓冲内接到门洞净空扇形，否则提示"两端都未衔接到门洞净空（入口）"。
- **规则 2 衔接路径不截断**：已衔接端头到对应门洞的走廊（端头边缘与门洞包围盒的并集包围盒，轴对齐近似）被家具占地（旋转外包）/禁放区/柱等挤占后，剩余净宽低于 `MIN_PASSAGE_MM`（600mm，策略值）时提示"衔接路径净宽不足"。净宽计算沿走廊较长轴在 blocker 边界处分段取交集，矩形输入下精确。门洞净空自身不算阻挡。
- **未标注门洞的空间**：有通道时提示"未标注门洞净空（入口）：通道与入口的连通未核验"，不做规则 1/2。

## 实现

- 新增纯函数模块 `frontend/app/utils/channelEgress.ts`：`channelEgressHints(zone, channels, furniture, firstBlockDepthMm?)` 返回提示文案数组；常量 `DOOR_LINK_BUFFER_MM`/`MIN_PASSAGE_MM` 注明策略值非规范。
- 排版面板（DesignLayoutSidebar）通道区下方展示提示（`data-testid="channel-egress-hint"`，amber 文案，与 023 宽度提示同级）；首排深度取已保存排版的 `firstBlockDepthMm` 记录，与确认校验口径一致。
- 复用：`channelRects`（027 裁剪 + 028 端点语义）、`clipRectToRingRects`（端头缓冲矩形 × 门洞扇形求交）、`officeFurnitureFootprint`（旋转占地）、`obstacleExclusion`（非门洞障碍）。
