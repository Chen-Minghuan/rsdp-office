# 任务记录模板

每项有独立目标、依赖或验收的开发工作使用一个稳定编号，例如 `GEOM-001`。
状态摘要写入 [进度表](../status.md)，任务文件保存过程和证据；二者状态保持一致。

## 模板

```markdown
# <编号> <具体任务名称>

状态：待开始 / 进行中 / 部分实现 / 已编码待验证 / 已验收 / 阻塞
更新日期：YYYY-MM-DD
负责人：按实际填写
基线/交付版本：提交号；未提交时写工作区，不伪造提交号
关联：需求章节、契约、依赖任务

## 目标与验收

触发：用户如何操作。
结果：操作后应发生什么。
范围：本任务包含的行为与后续任务边界。

- [ ] 验收项 1：输入、预期结果、验证方法
- [ ] 验收项 2：异常、恢复和版本行为

## 现状与依赖

已存在的代码与证据；缺口；所需服务、样本或其他任务。
待明确的问题写清影响，不假装已经确定。

## 实施步骤

- [ ] 明确输入输出与版本/单位
- [ ] 实现必要模块与交互
- [ ] 执行与范围对应的验证
- [ ] 更新相关文档及状态表

## 决策与过程

| 日期 | 发现/决定 | 原因或证据 | 对下一步的影响 |
| --- | --- | --- | --- |
| YYYY-MM-DD | 按实际填写 | 源码、样本或测试 | 按实际填写 |

## 验证记录

| 日期 | 版本/环境/样本 | 命令或操作 | 结果及证据 | 未覆盖项 |
| --- | --- | --- | --- | --- |
| YYYY-MM-DD | 真实/模拟、样本哈希 | 实际执行内容 | 通过/失败/未执行 | 如实填写 |

## 交付与下一步

变更文件、行为变化、验收结论、剩余限制与后续任务。
阻塞时写具体条件和解除方式。
```

只保存接续开发所需的信息，不逐条复制聊天或工具调用。
一个阶段已完成但整个功能尚未完成时拆成明确子任务，避免提前把整项标为已验收。
