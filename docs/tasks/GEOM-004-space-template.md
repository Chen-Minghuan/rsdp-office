# GEOM-004 空间模板与布局复用

状态：已实现并通过专项与数据库集成验证
更新日期：2026-10-15
依据：用户要求空间编辑完成后生成整层空间模板，类似彩色分区图，用于后续布局和排版；不恢复逐空间确认门槛。

## 范围与契约

- 模板保存当前毫米空间的名称、用途、稳定 ID、多边形及面积、来源/比例和质量提示。预览为彩色真实轮廓分区图，缺失的门窗/墙体层保持 UNKNOWN，不伪造完整识别。
- 模板是独立不可变快照；同项目可保存多个版本/模板，列表可重新取用。编辑当前画布不会改写旧模板，几何/用途变化后提示需要更新。
- 进入布局捕获当前空间模板；显式保存的模板持久化到 Java/PostgreSQL。局部本地快照与服务端已保存模板分别标识，保存失败不能显示已保存。
- 使用历史模板新建布局为可撤销替换，模板不含当前家具/购物车，不静默清空已有方案。仅在用户明确使用模板时创建独立设计副本。
- 未知比例/非法轮廓仍阻止生成精确模板，识别候选/重叠提示不要求逐个确认。生成/保存中的过期响应不覆盖新草稿。
- 复用既有 SpatialSceneSnapshot 作为模板内容及统一几何/单位；暂不迁移整个 Office Canvas 到旧 DesignScene 确认 API。

## 验证计划

Java：毫米校验、派生面积、异形保留、保存幂等、项目隔离与快照不变。
UI：彩色模板预览、保存/失败反馈、历史加载、编辑后过期、使用独立副本/撤销、排版引用模板及刷新。
构建、现有空间/尺寸回归与实际数据库创建/读取单独记录。

## 实现

- `SpaceTemplatePlan` 以同一毫米多边形绘制彩色整层分区，不重排房间；L 形及孔洞预览保留，标签按空间内部取点并随视口保持可读。`SpaceTemplateDialog` 提供名称/面积/空间列表、保存、历史读取、导出及新建布局入口。
- 沿用 `SpatialSceneSnapshot` 1.2；Java 核验 WORLD_MM、可靠比例、ID 与合法多边形，重新计算房间面积。孔洞与实心障碍使用并集/差集避免重复扣除；面积合计为房间面积之和，重叠提示不拦截。
- `office_space_template` 记录来源分析 ID/版本、画布修订、内容哈希和 scene_json。保存仅新增快照；clientChangeId 重试幂等，同 ID 异内容拒绝。GET 列表限最近 50 个摘要，详情含完整快照，均按 projectId 查询。
- 工作台“生成空间模板”打开当前快照；保存成功才标记远端已保存。直接进入排版会先捕获本地模板；空间/家具分别记录 spaceTemplateId/templateSpaceId，原始识别仍保留。
- 使用历史模板仅在用户明确点击后替换当前画布空间/家具，可撤销；已有方案清单保留并提示核对。新副本不再携带旧识别 URL，以免刷新后重导入。`NuxtPage` 在核对/设计切换时保留同一实例，避免外层布局切换导致路由与 store 重置。
- 模板包含建筑约束层时可保存/预览/导出，但兼容 Office Canvas 目前不能处理的孔洞/墙/门窗/障碍、嵌套空间及边界关系会明确禁止用于该排版器；不静默删除。这不是完整建筑层识别或异形家具排版验收。

## 数据库与启动

在仓库根目录显式执行（当前本地环境已执行）：

```bash
docker exec -i office-postgres psql -v ON_ERROR_STOP=1 -U postgres -d office < backend/src/main/resources/db/migrations/V20261015__space_template.sql
```

随后重启 Java；本地当前 8082 已载入新代码，保持仓库根目录为工作目录以读取原 uploads。未增加新服务或改用其他解析器。
