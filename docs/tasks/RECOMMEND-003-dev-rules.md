1. **不改匹配内核**：品类相关性、尺寸贴合匹配（`OfficeProductMatching` / 尺寸硬门槛 / relevanceScore 排序）一行不动。颜色只是展示层过滤。

## 3. 业务规则红线（来自任务方案，不可擅自变更）

1. **级联判定链**：颜色名规则推断 → 图片亮度 → 未知；人工修正（来源=MANUAL）优先级最高，任何重算/回填不得覆盖 MANUAL 值。
2. **组合色拆分**：分组与搜索 = 多标签（「+」「/」「、」切分，每个色词都产生归属）；深浅判定 = 单标签（只取第一个色词/最大色簇）；卡片展示完整原文、色块只画主色。
3. **点缀色豁免**：「橙/红/金」等高饱和小面积色在规则词表中直接跳过，不参与深浅判定，仅作展示标签。
4. **非颜色词处理**：词表白名单只认颜色词；「电力轨道」等功能词不产生标签、不报错，全部未命中才降级图片路径。
5. **无数据兜底**：无颜色数据且无图 → tone=未知，进「未分组」，正常出现在「全部」中，不得影响推荐主流程。
6. **中性模糊带**：110~150（校准值为准）不参与深浅筛选，只在「全部」出现；不得把模糊带商品硬判深/浅。
7. **尺寸优先**：色系过滤插入现有 candidates computed，与尺寸分档（全部/贴合/宽松/偏小）叠加生效，顺序与语义与尺寸档位同构。
8. **动态筛选项**：色系/颜色筛选项从当前模块候选实际出现的颜色生成；数量为 0 的项不显示或置灰标 0，不允许筛出空列表。

## 4. 代码约定

### 4.1 rsdp 主项目侧（Java）

- 遵守 `rsdp/AGENTS.md` 第五节编码规范：Java 21、Lombok、DTO 按 request/response 分包、新增 public 方法必写 JavaDoc。
- 改动点最小化：`OfficeProductDto` 仅增加 colorText / colorPrimaryName / colorTone / colorHex（可选）；`RsdpCatalogGateway.toOfficeProductDtos` 填充透出。
- 色系判定逻辑放独立可测的服务/工具类（输入=颜色原文+图片，输出=tone+source），不写进 Controller，不散落在导入流程各处。
- 判定结果带来源标记（RULE / IMAGE / MANUAL / NONE），入库可追溯。
- 导入确认页人工修正走既有更新链路，修正即写库并标记 MANUAL。
- 历史数据回填做成一次性幂等脚本/任务，同一条级联链离线跑；可重复执行，不覆盖 MANUAL。

### 4.2 数据库改动（如 colorTone 需落库）

- 遵守主项目同步约定：编辑 `database/schema/` 对应域文件 + 同步 `ops/reset_db.sql` + 新增 Flyway V 增量脚本，三处一致；发布前跑 `make check-migration-sync`。
- 所有 DDL 幂等（IF NOT EXISTS / IF EXISTS 守卫）。
- 实体/表结构改动后运行 `node scripts/check_entity_db_fields.js` 对账。
- 注意主项目编码铁律：颜色/色系是属性，绝不进入 RSPU/RSKU 编码与主键。

### 4.3 rsdp-office 前端侧

- 沿用 Nuxt/Vue/Pinia 现有目录与风格；类型定义齐全，核心判定/分组/搜索逻辑放有明确输入输出的模块（如 composable 或纯函数 util），不写进模板事件里。
- 搜索匹配字段 = 主色 + 颜色原文（含拆分后的全部色词）+ 商品名 + 变体摘要；规范化统一处理大小写、空格、全半角；别名表与分组/深浅共用同一份词表数据，不复制三份。
- 页面状态完整：加载中 / 无候选 / 筛选后为空 / 未分组，各有明确展示；空态不得表现为加载失败。
- 筛选项计数与候选列表保持同一份 computed 数据源，不出现计数与列表不一致。

### 5.2 本任务必补用例

- 判定链单测：规则命中（黑/深/白/浅等关键词）、规则未命中降级图片、无图 → 未知、MANUAL 不被重算覆盖、组合色取第一个色定深浅、点缀色跳过、非颜色词忽略。
- 规范化单测：大小写、空格、全半角、「+」「/」「、」三种分隔符。
- 前端用例：深色系筛选后列表只含深色；搜索「胡桃」命中 月影胡桃/蜜芽胡桃/（别名）雾山核桃；色系 + 尺寸分档叠加；无颜色数据商品进「未分组」；数量为 0 的筛选项行为。
- 真实样本：四个供应商 Excel 产品图的判定结果记录（文件来源 + 预期 + 实际），标注准确率。

## 7. 一句话总结

> 颜色是展示层过滤器：判定链在导入时一次算清（规则 → 图片 → 人工兜底），前端在现有候选上分组/筛选/搜索，匹配内核零改动，每个决策和每次验证都留痕。
