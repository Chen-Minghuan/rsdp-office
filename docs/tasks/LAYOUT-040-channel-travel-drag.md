# LAYOUT-040 通道沿走向拖动与端点拖柄

关联：[LAYOUT-021](LAYOUT-021-canvas-aisle-channels.md)；[LAYOUT-028](LAYOUT-028-channel-endpoint-breaks.md)（其"走向端点拖柄留作后续交互增强"即本卡）；[LAYOUT-013](LAYOUT-013-layout-panel-ux.md)

## 目标与验收

触发：用户反馈"竖形的通道应该可以上下调节，横型的通道应该可以左右调节"——条带拖动只响应垂直于走向的分量（改位置），沿走向只能进编辑卡输数值。
结果：条带拖动同时响应走向分量，有限通道（设 startMm/endMm）可沿轴整体平移起止窗口；选中后走向两端出现端点拖柄，单独调整起点/终点，拖回边界恢复该端贯通。

- [x] 验收项 1：竖向通道上下拖、横向通道左右拖可平移起止窗口，位置（offsetMm）不变，不越出包围盒
- [x] 验收项 2：端点拖柄单端调整 startMm/endMm，保持 起<止，拖回边界恢复贯通（undefined）
- [x] 验收项 3：贯通通道走向分量不响应（无可动空间），位置拖动/宽度拖柄/吸附等既有行为不回归

## 定稿语义（2026-11-05）

- **只编辑显式字段**：走向拖动与端点拖柄只改 `startMm`/`endMm`；「仅从二排起」（fromSecondRow）的动态起点语义不冻结、不联动（与 LAYOUT-028 决策一致）。画布条带渲染本就不含 firstBlockDepthMm，手柄位置与渲染一致。
- **钳制**：平移增量钳制使窗口两端都在包围盒走向区间内（`channelTravelDeltaRange`）；端点值钳制在包围盒内且与另一端保持 ≥1mm（`clampChannelTravelEndpoint`）。平移/拖动后贴到边界的一端恢复 `undefined`（贯通），不产生 0 长度或贴边残值。
- **贯通通道走向不响应**：两端都贴包围盒时增量区间恒为 [0,0]，上下/左右拖无效果（光标保持 ew/ns-resize；有限通道为 move）。
- **走向分量不参与吸附**：吸附仍只作用于垂直走向的位置分量（LAYOUT-026 语义不变）；走向端点对家具/墙的吸附留作后续增强。
- **凹形空间预览近似**：多边形裁剪输出的多段矩形在拖动预览中整体平移/伸缩，松手提交后按真实几何重算分段（与既有位置/宽度预览同一取舍）。
- 提交沿用 `updateZoneChannels` 同一失效与撤销链路：本空间排版确认与已提交方案失效，不影响其他空间。

## 实现

- 纯函数（`utils/layoutChannels.ts`）：`channelTravelSpan`（走向轴包围盒区间）、`channelTravelDeltaRange`（平移增量区间）、`shiftChannelTravel`（整体平移补丁，贴边恢复贯通）、`clampChannelTravelEndpoint`（单端钳制，触界返回 undefined）。
- 画布（`CanvasBoard.vue`）：条带拖动新增走向分量 `dt`（预览即钳制）；新增 `channel-travel` 拖动模式与走向两端手柄（紫色，与蓝色宽度手柄区分，恒定屏幕尺寸，挂在最大分段上）；条带光标按是否有限通道切换 move/resize；编辑卡操作提示更新。
- 数值入口不变：编辑卡与排版面板的起点/终点输入仍是同一字段的另一入口。
