# RECOG-010 越界输出导致中央开放办公区丢失

日期：2026-10-17。状态：已实现失败响应回归；正式新识别与全图边界验收待执行。

## 当前截图的实际原因

只读检查 `FPA-5C32CDA8`，7.png，创建于 14:09:33。标准图仍为 1849×1270，SHA256 `6c2256aaddec3f1aa2c93dc35b413bb22752d544914bd29f8c7efa83ff1804cf`，当前服务返回 V5。

原始模型输出 18 个候选，包含“开放办公区(38人)”。这个轮廓的 X 达到 1175，超出了约定的归一化 0..1000；两间右侧主管室和两个未命名候选也越界。API 适配拒绝无效几何，所以截图中的中央空间消失；不是前端漏画一个有效房间。

另一个连带问题：同名匹配要求组内所有初稿均可解析，某个主管室越界便禁用了六处文字的一一匹配。截图中四处主管室继续显示错误初稿，两处被过滤；当前 V5 只沿墙恢复了男卫与两间会议室。

## 修复范围

- V7 的同名匹配只把有限初稿坐标用于一一分配成本，允许该阶段读取越界位置；这些位置不作为最终几何。无效单行不再使整个同名组失败，最终轮廓必须从独立文字位置沿实际墙线获得，并通过既有多边形/归属检查。无独立文字时仍不应用越界初稿。
- 对越界、自交、缺失，或与独立房名冲突的 OPEN_OFFICE 候选增加独立的开放区恢复；已有有效原候选不强制重写。独立文字检测明确发现开放办公名称而主请求漏列时，可创建低置信候选再追踪，人数括号保留，全角/半角括号统一匹配。
- 开放区按结构墙网追踪，排除已获得墙线证据的周边房间，以及其他房名内侧文字框触及的独占弱线区域。文字落在隔断时，使用文字框内部多点，不虚构整房框。只有页面内封闭、几何有效、足够大的区域才恢复；越过页面、吞并其他房名、覆盖已恢复房间或多个开放区归属冲突时拒绝。不把无效初稿直接截到 0..1000，也不以包围盒替代凹角。
- `openSpaceRecovery` 单独记录 STRUCTURAL_FREE_FLOOR、种子来源、恢复数量和 RECOVERED_NEEDS_REVIEW。它不计入封闭房间 acceptedCount，保持 `contourGrounded=false` / low，不生成毫米尺寸或人工确认。来源 `initialModelOutput` 不变，现有用户草稿不自动覆盖。
- 两路原有 AI 请求仍并行；提示词补充中央办公区域完整性检查，确定性补救不追加 AI 请求，也不把提示词视为精度证据。
