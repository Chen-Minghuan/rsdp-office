# RECOG-005 房名定位与同图轮廓继承

日期：2026-10-16。状态：部分实现；当前图棋牌室自动定位通过，开放分区自动边界仍未验收。

## 问题与实际边界

用户指出棋牌室应在右侧，过道、吧区、休闲区仍然错位。此前逐次改画布后，用户重新识别会得到新的 analysis/room ID；仅按旧 ID 修正无法解决重复错位。V1 墙线程序使用模型多边形中心作为种子，并排除了 LOUNGE/HALLWAY 等类型，不能纠正棋牌室的语义位置。

本次不把人工修正或通过单测当作自动识别准确率验收。开放区域没有完整围墙，模型独立看整图仍给出错误边界，必须明确保留此缺口。

## 实现

- 直连 Qwen 的整图识别在墙线校正前增加一次独立房名文字框检测，只发同一张完整底图，不混入尺寸放大图。按唯一、有效的房名文字框中心定位，再沿原图墙线取封闭区域；不再根据候选多边形中心猜该房间的位置，也不依赖模型将棋牌室分成哪一种类型。
- 房名重名、无可靠文字框、多名共用一个连通区域、墙线未闭合、几何无效均不自动合并。独立房名与原候选不符时明确提示；未解决候选降为 low。门洞补线仍是估计，不自动确认尺度或空间。
- `initialModelOutput`、独立 `labelLocalization`（含请求 ID）和 `contourRefinement` V2 证据分别保留。单独尺寸识别不新增房名请求；关闭 `RSDP_VISION_REFINE_ROOM_CONTOURS` 同时关闭此步骤。
- 分析详情新增 `imageSha256`、`designCorrections` 和房间 `contourGrounded`。`rooms` 仍为该次识别原始房间；人工校正作为独立设计覆盖层返回。
- `OfficeCanvasMapper.selectCorrectionSnapshots` 从已有画布历史按项目、标准底图哈希、来源识别版本、唯一房名取最近人工几何。不按数组序号或新旧 room ID 关联，不限于最近若干自动保存，不新增表或迁移。
- 后端重新检查来源项目/哈希、像素单位、轮廓合法性和页面边界；毫米稿按该稿的 `mmPerSourceUnit` 还原到来源像素。不同底图、CAD、演示、重名和无比例的毫米稿不继承。
- 前端导入新批次时仅对唯一同名空间应用这些轮廓；`sourcePolygon`、新空间 ID 和新来源版本保留，证据明确为 MANUAL，仍需当前图比例校准，未伪造人工确认。页面复核信息显示“沿用同一底图的人工修正轮廓”。同一批次刷新仍保留现有设计。
- 对已有独立房名/墙线定位的封闭房间，若历史人工框与新房间完全不相交，不让旧错位框覆盖它。开放功能分区仍沿用用户划定边界。

6. 将本次新的真实 Qwen 输出、数据库读取的 12 处校正与实际前端 `applyDesignCorrections` 组合验证：15 个空间有效且无两两重叠，十处本次目标与标注包一致（毫米还原比较容差 0.000001 来源像素），所有 `sourcePolygon` 保留。产物 `/tmp/rsdp-real-reuse-result.json`；这是分段真实数据组合验证，尚未运行中新后端的正式完整上传验收。
