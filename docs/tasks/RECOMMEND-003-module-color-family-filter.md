## 总体设计

一个数据源（主色）+ 一条级联判定链 + 三个前端能力（分组/筛选/搜索），全部增量叠加在现有推荐之上，不改动匹配与排序内核。

### 1. 数据层：字段透出与色系字段

- OfficeProductDto 增加 colorText（变体颜色原文）、colorPrimaryName（产品主色）、colorTone（深/浅/中性/未知）、colorHex（可选，主色色值用于卡片色块）。
- RsdpCatalogGateway.toOfficeProductDtos 中从变体 JSON / RSPU 填上述字段。
- 色系判定结果 colorTone 存于主项目侧（RSPU 或变体级，见「待决策 1」），网关读取透传；office 侧不重复存储。

### 2. 色系判定级联链（导入时计算，一次计算永久使用）

```
有主色/颜色原文？
├─ 是 → 规范化颜色名（去空格/全半角/+号统一）
│        ├─ 关键词推断：黑/深/暗/墨/炭/咖 → 深；白/浅/米/银/亮 → 浅
│        ├─ 推断成功 → 记录 tone，来源=RULE
│        └─ 推断失败 ↓
└─ 否/推断失败 → 主图亮度计算（见 §3），来源=IMAGE
        └─ 无图 → tone=未知，来源=NONE
人工在导入确认页修正 → 来源=MANUAL（优先级最高，不被重算覆盖）
```

组合色（如 雾山核桃+液态银）取「+」前第一个色为主色判定深浅；完整原文仍用于分组与搜索。

### 3. 深浅算法（图片路径）

- 感知亮度：Y = 0.299R + 0.587G + 0.114B（0~255）。
- 主体提取（由简到繁，先 1 验证）：
  1. 中心裁剪：缩图至 64×64 后取中心 50% 区域求平均亮度；
  2. 去背景色：取四角像素为背景色并剔除相近像素后求平均；
  3. 主色聚类：中位切分/k-means 取 3~5 色，排除背景簇，最大簇即主色，同时产出 colorHex。
- 阈值：以 128 为初值，用真实样本校准后固化；110~150 设「中性模糊带」不参与深浅筛选。
- 参考分布（需实验确认）：暮山黑橡 ≈40~70，月影胡桃 ≈60~90，雅士白/液态银 ≈170~220。

### 4. 前端推荐面板

- 候选卡片：新增颜色小色块 + 主色名标签（如「月影胡桃」）。
- 筛选行：在尺寸分档按钮上方增加色系筛选：全部 | 深色 | 浅色（中性/未知仅在「全部」出现）。
- 搜索框：占位提示「试试：黑橡、胡桃、白色」；匹配字段 = 主色 + 颜色原文 + 商品名 + 变体摘要。
- 分组排序：同主色候选相邻展示（色系分组 → 组内按现有 relevanceScore 排序），不打乱现有排序逻辑。
- 三个过滤条件（搜索 ∩ 色系 ∩ 尺寸档）在前端对 result.candidates 做「与」过滤；result 已有全量候选，无新接口。

### 5. 搜索模糊规则

- 第一层 规范化（必做）：忽略大小写、空格、全半角、「+」。
- 第二层 颜色别名表（建议）：胡桃 → 月影胡桃/蜜芽胡桃；核桃 → 雾山核桃；黑橡 → 暮山黑橡。与关键词推断共用同一张颜色小词表（一份维护，三处使用：分组、深浅规则、搜索别名）。
- 第三层 拼音（暂不做）：候选集规模小，浏览成本低于输入拼音。

### 6. 导入确认页联动

- 「主色」旁展示自动判定的色系徽标（深/浅/中性/未知 + 来源标签：规则/图片/人工）。
- 操作员可下拉修正；修正值写回主项目，MANUAL 来源不被后续重算覆盖。

## 参考：电商搜索架构对照（2026-11-18 讨论）

经典电商「颜色搜索」链路（属性标签 → 搜索引擎+NLP → CV 识图 → 向量检索 → 排序）与本方案的映射：

| 电商搜索概念 | 本方案对应 | 取舍 |
| --- | --- | --- |
| 商品属性字段（color） | colorPrimaryName / colorText | 已存在，透出即用 |
| 属性归一化 + 同义词词典 | 颜色词表 + 别名表（分组/深浅/搜索三处共用） | 采用，小规模人工维护 |
| 倒排索引 / Elasticsearch | 不引入：候选已按品类+尺寸收敛到数十条并全量在前端内存，前端 filter 即可 | 明确不做，避免过度架构 |
| CV 识图取色 | 图片亮度计算（降级路径） | 采用，先定位主体再取色 |
| 深度学习 / VLM 属性识别 | 二期可选：项目已有 Qwen-VL 集成（RECOG-002），可直接问「主色调深还是浅」 | 候选增强，非一期 |
| 向量检索 / CLIP | 不采用：颜色要求精确匹配，向量相似不等于属性匹配（橙色≈黄色的误判不可接受） | 明确不做 |
| 检索与排序分离 | 架构一致：品类+尺寸匹配内核不动，颜色仅作过滤层，relevanceScore 排序不变 | 已遵守 |

从该架构吸收的两个要点：

1. **先定位主体再取色**（原文关键警告：模特穿黄衣、背景蓝色时不能对整图求平均）。这直接支持 §3 的防背景三级策略，否定"整图平均亮度"的偷懒做法。
2. **颜色空间升级**：明暗判定除 RGB 感知亮度外，可改用 HSV 的 V 通道或 Lab 的 L 通道——更接近人眼感知，且方便把「木纹棕」这类低亮度高饱和色与「深灰」区分开。验证 B 同时输出 Y 与 V/L 两组值对照后再定。

## 决策补充：组合色的标签策略（2026-11-18）

参考电商视觉检索中「多色商品如何标注」的难点（主体分割/颜色占比/多标签/置信度），对组合色（如 蜜芽胡桃+雅士白+爱马仕橙）确定为：

- **分组与搜索：多标签**。颜色原文按「+」拆出的每个色都参与分组和搜索——用户在「白色系」分组里也能找到 蜜芽胡桃+雅士白 的家具。
- **深浅判定：单标签**。一件家具不能又深又浅：取占比最大的主色（「+」前第一个；图片路径则用最大色簇）判定唯一 colorTone。
- **点缀色豁免**：高饱和小面积色（如 爱马仕橙）不参与深浅判定，仅作标签展示；规则词表中对「橙/红/金」等点缀色直接跳过。

## 组合色多标签方案（2026-11-18 补充，替代"待决策"中组合色部分）

问题原型：蜜芽胡桃+雅士白+爱马仕橙、雾山核桃+液态银。一件衣服同时有黄白黑该标什么颜色——产业实践的答案是：分组多标签、判定单标签。

### 拆分原则：同一件商品，不同维度不同答案

| 维度 | 策略 | 理由 |
| --- | --- | --- |
| 色系分组 | 多标签：组合色每个色词都产生分组归属，一件商品可同时出现在「蜜芽胡桃组」和「雅士白组」 | 用户找"白色系家具"时理应能找到白+橙的款；分组是召回逻辑，宁多勿漏 |
| 深浅判定 | 单标签：只取第一个色（主色）判定深浅 | 一件家具不能又深又浅；第一个色通常是视觉主体、占比最大；与"主色"字段语义一致 |
| 搜索匹配 | 多标签：完整颜色原文全部参与匹配 | 搜"爱马仕橙"应命中 蜜芽胡桃+爱马仕橙 |
| 卡片展示 | 显示完整原文（蜜芽胡桃+雅士白），色块只画主色 | 信息完整但视觉不混乱 |

### 组合色解析规则

1. 以「+」「/」「、」切分颜色原文，得到色词列表。
2. 每个色词经规范化（去空格/全半角）后查颜色词表：
   - 命中 → 产生一个分组标签；第一个命中的色词定深浅。
   - 未命中（如混入的「电力轨道」等功能词）→ 不产生标签，不影响其他色词。
3. 全部未命中 → 该商品走图片亮度路径判深浅，分组进「未分组」。

### 例

| 颜色原文 | 分组标签 | 深浅判定 | 搜索可命中词 |
| --- | --- | --- | --- |
| 月影胡桃+海鸥灰 | 月影胡桃、海鸥灰 | 按「月影胡桃」→ 深 | 月影胡桃、海鸥灰、胡桃 |
| 暮山黑橡+深灰银钢脚+电力轨道 | 暮山黑橡、深灰银 | 按暮山黑橡 → 深（「电力轨道」不入表） | 暮山黑橡、黑橡 |
| 蜜芽胡桃+雅士白+爱马仕橙 | 蜜芽胡桃、雅士白、爱马仕橙 | 按蜜芽胡桃 → 浅 | 胡桃、雅士白、爱马仕橙 |
| （无颜色数据） | 未分组 | 图片亮度路径 | 商品名、变体摘要 |

## 约束关系：颜色在尺寸之后（2026-11-18 代码核实）

代码事实（OfficeProductMatching.orientation / OfficeModuleRecommendationService.recommendations / ModuleProductRecommendations.vue:21）：

1. 尺寸是后端硬门槛：商品宽深超过模块宽深（含 90° 旋转判定）直接淘汰，不进入候选。
2. 尺寸分档（CLOSE/RELAXED/SMALL）只是标签，后端返回全部放得下的候选。
3. 档位过滤在前端 candidates computed 中完成；色系过滤与搜索与之同构，插入同一 computed，零匹配逻辑改动。
4. 选择时服务端 selectModuleProduct 重新校验尺寸与在售状态；颜色过滤纯属展示层，不影响选择安全性。
5. 色系筛选项从当前模块候选中实际出现的颜色动态生成；候选中不存在的颜色不显示（或置灰并标注数量 0），避免筛选出空列表。
6. 「同步 N 个同规格模块」应用的是已选商品本身，颜色随商品自然同步，无需额外处理。

| 暮山黑橡+灯带 | 2 | 99.2 | 90~108 |
| 纳柯+液态银 | 22 | 112.0 | 69~157 |
| 月影胡桃+海鸥灰 | 6 | 127.8 | 94~162 |
| 蜜芽胡桃+雅士白 | 29 | 182.4 | 152~242 |
| 雅士白+爱马仕橙 | 2 | 253.6 | 252~255 |

结论：
1. 大方向有相关性（深色木作 < 130 < 浅色系列），但组内方差大、组间有重叠。
2. 出现明确反例：「液态银+玛德德岩板」Y=67.5 会被误判为深色系——场景渲染图暗背景/灯带高光干扰严重，证实"整图/中心平均亮度"不足以单独作为判定依据。
3. 决策：维持级联设计——颜色名规则推断为主（可信），图片亮度仅作最终降级路径且必须经人工确认；「液态银/银/金属」类关键词规则应覆盖金属银色系，避免落入图片路径。
4. 图片路径若启用，需先做主体分割（去背景/主色聚类），不能用中心平均；阈值实验在改进主体提取后重做。
