# LAYOUT-013 排版面板操作体验

## 2026-10-29 会议长边座椅居中修正

会议场景横排椅子的 X 坐标此前以 `tableX`（桌面左缘）为对称中心，漏加桌长的一半，导致上下两排各 4 把椅子整体偏向桌子左端。现改为相对桌面中心排列，椅子仍保持在桌面覆盖范围内，短边相向座椅不变。新增两排数量、排中心与桌中心一致、椅子不超出桌面覆盖范围的回归断言。

`pnpm test:mixed-layout`、`pnpm build` 与 `pnpm e2e:layout-planning` 通过。真实会议室三种候选的上下排中心均与桌面中心一致，并已人工核查实际组合预览；未应用或覆盖正式家具。UI 回归使用模拟 API。

## 2026-10-29 门洞净空坐标重复转换修复

`zoneLayoutExclusions` 已将建筑约束从存储坐标转换为画布排版坐标，组合布局此前又执行一次 Y 轴翻转，导致门洞被映射到房间另一侧，右上沿墙柜因此漏判。现组合布局直接复用其输出，不再二次转换；全空间禁放回归数据也改为真实的存储坐标，并新增玄关柜不得压占门洞净空的断言。

`pnpm test:mixed-layout`、`pnpm build` 与 `pnpm e2e:layout-planning` 通过。真实会议室（约 8343×4779mm）只读复算三种候选均为会议桌居中、10 把椅子围绕长边两侧和短边布置，所有玄关柜与门洞净空碰撞检查均为 `false`；未覆盖现有正式家具。UI 回归使用模拟 API。

## 2026-10-29 会议区居中与锚点评分优化

针对三种候选都把主要会议区挤在角落的问题，调整功能包锚点与排序：会议场景整体居中，不再只有会客优先策略才居中；玄关/吧台分别提供右上、右下、左下沿墙位置，保持主体功能区分明。候选排序在目标缺口和跳过品类之后，先比较会议区中心偏移，再比较紧凑度，避免单纯因挤得更紧而胜出；无工位时默认策略名调整为“会议居中 · 功能分区”。

`test:mixed-layout` 新增会议区中心坐标与多种收纳位置断言，真实会议室只读复算三种候选均为会议桌居中、玄关柜沿不同墙边。`pnpm build`、`pnpm e2e:layout-planning` 和 `git diff --check` 通过。

## 2026-10-29 功能包改为真实场景组合

针对组合效果只是主家具与配件逐行拼接的问题，功能包改为按使用关系组织：会议/茶餐场景桌子居中，椅子沿长边两侧和短边布置并带相向旋转；沙发/会客场景形成沙发—茶几—座椅的交流区，不再全部排成一行。功能包记录每件家具的旋转角度，预览、应用和碰撞检查共用同一几何，保留真实毫米尺寸、建筑约束和通道限制。

候选仍按工位集中、会客优先、沿墙收纳比较，优先目标达成和完整功能包，再比较紧凑度，不以塞满空间为目标。真实会议室只读复算已生成桌居中、长边双侧及短边相向座椅的 11 件组合；`test:mixed-layout` 新增多侧座椅、短边朝向和会客交流区断言，`pnpm build`、`pnpm e2e:layout-planning` 与 `git diff --check` 通过。

## 2026-10-29 组合布局整体候选与选择后再出图

按用户反馈，功能模块选择不再立即生成默认模块预览。单模块只在选择排布、显式勾选预览或应用时出图；多模块改为「生成组合预览」→ 选择候选 →「应用所选组合」。候选切换只改预览，不写正式家具。

`planMixedLayout` 从固定包顺序摆放改为整体候选求解：提供工位集中、会客优先、沿墙收纳三种策略，分别尝试工位网格、中央组合和沿墙位置，再回退到有序空位。按目标座位缺口、跳过品类数量与紧凑度排序，最多保留 3 个不同候选并展示利用率/人均余量。所有候选统一校验真实轮廓、保留家具、建筑约束和通道，不缩放家具；`zoneLayoutExclusions` 已输出画布排版坐标，组合布局直接复用，禁止二次翻转。`applyMixedLayoutProposal` 接收候选索引，预览与应用使用同一几何，保留手动家具和一次撤销。

验证（UI API 均为模拟）：`pnpm test:mixed-layout`（多候选、目标人数、禁放区与通道）、`pnpm build`、`pnpm e2e:layout-planning`（选择不出图、生成后出图、候选切换、应用一致及撤销）、module-selection、auto-layout 和 `git diff --check` 通过。

## 2026-10-29 自动布局与手动排版并列

按用户确认，「自动布局」和「产品选型」不是必须先自动、再手动的递进步骤，而是两种可独立使用、可随时切换的排版方式。自动布局继续按所选功能模块、实际空间、目标人数、间距和建筑约束生成方案，并展示座位排列推荐及 Top N 候选；完成后可直接确认并进入款式推荐，也可进入产品选型手动调整。产品选型集中提供位置、尺寸、旋转、复制、删除、逐件添加、清空和确认，空布局也可直接手动开始，不再要求先经过自动布局。

图例主卡片用于手动选择与替换：选中已排家具后点击新图例，保留家具 ID、中心位置和旋转，采用新模块的图例与毫米宽深；无选中家具时只选定图例，不再默认跳回自动布局。每个图例另有独立「自动」按钮，供用户显式用于自动布局；「逐件」用于手动添加。新增 `replaceFurnitureModule` 复用边界/重叠/禁放区硬校验，替换失败不改旧家具；成功后使当前空间确认和方案失效，清除旧商品匹配并扣减对应清单数量，支持一次撤销与既有持久化。自定义模块保留独立快照。款式推荐继续要求先确认排版，不因并列入口绕过阶段校验。自动布局页也提供统一「清空排版」：清空当前空间家具和待应用预览，同时取消全部已选功能模块，不限于产品选型页。按后续反馈，操作区不再展示人均面积、边缘补位、椅背净距和未核验等黄色/说明性策略提示，只保留会阻止应用或确认的红色错误；布局计算和确认规则不变。

验证（UI API 均为模拟）：`pnpm build`、module-recommendations（替换/旧选品清理/复制/撤销）、module-selection（自动布局确认并直达推荐）、layout-planning（含自动布局清空与模块取消选择）、auto-layout、adaptive-layout、furniture-modules、custom-modules、reference-layouts、layout-references、single-space、delete-modules、workflows 和 MOCK smoke 通过；`git diff --check` 通过。通道长专项在确认阶段等待「重新调整排版」超时，未记为通过，也未据此完成全量业务验收。

## 背景与目标

原排版侧栏同时展开模块目录、产品样式、排布方式、尺寸和间距，窄侧栏中需要连续滚动查找，应用、逐件添加和清空也形成多个同权重按钮。本次将操作收束为明确的三步流程，减少视觉拥挤并保留原有排版能力。

## 交互方案

1. 顶部使用“模块 / 参数 / 排布”三步导航，当前步骤高亮，并在下方显示当前模块和产品样式摘要。
2. “模块”步骤只处理目录选择和自定义模块；“参数”步骤先处理模块毫米尺寸和空间间距；“排布”步骤最后处理产品样式及图例排布。
3. 排布步骤提供当前模块快捷卡片，点击即可回到模块步骤更换模块。
4. 底部固定为当前/预估件数摘要、一个主应用按钮，以及“逐件添加 / 清空排版”次操作；确认排版单独保留为状态按钮。
5. 保留已有 `data-testid`、按钮文案语义、规则默认值和布局保存契约，界面调整不改变排版算法。

## 验收标准

- [x] 三步导航可在不丢失当前选择的情况下切换。
- [x] 默认从模块步骤开始，完成模块和参数后再进入排布步骤；尺寸或间距变化时，已应用方案标记为待重新应用。
- [x] 当前模块、样式、预估数量和应用入口在不滚动的情况下可见。
- [x] 模块目录、尺寸编辑、间距编辑、逐件添加、清空和确认操作仍可用。
- [ ] 浏览器视觉回归确认不同窗口宽度下的滚动、文字密度和按钮可达性；当前环境缺少 Playwright 浏览器可执行文件。
