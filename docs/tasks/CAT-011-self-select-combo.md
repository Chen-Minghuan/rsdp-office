# CAT-011 商品库自选组合

## 目标与范围

商品库 `/products` 的“自选组合”：命名创建组合（每账号≤10 个）、拖拽商品卡或组合空位＋弹选品窗加入商品（每组≤5 个）、缩略图网格拼贴、展开/收起明细、重命名、删除确认。组合归属个人，可在产品方案页应用；不改动商品卡现有项目收藏＋与个人收藏♥。

设计文档：`docs/superpowers/specs/2026-11-23-self-select-combo-design.md`；渲染图确认方案 A（网格拼贴、名称与操作置顶）。

## 实现（2026-11-26 按组长评审整合到 product-bundles）

- **复用既有后端**：完全使用 `OfficeProductBundleService` 与 `/api/v1/office/product-bundles`（真实商品与本地商品、变体、数量、revision 乐观锁、可应用房间方案）。评审前本 PR 自建的 `office_combo` 表、迁移、TypeHandler、服务、控制器与测试已全部移除，不再存在第二套数据契约；组长指出的全量目录读取、真实 PG 验证均针对已删除代码，不再需要。
- **前端整合**：`ProductComboPanel.vue` 替换商品库收藏侧栏中的旧 `ProductBundlePanel`，保留多组合卡片管理：命名弹窗创建/重命名、删除确认、网格拼贴（失效商品标注）、展开/收起明细（名称链接到商品详情、变体与数量展示）、拖拽与空位＋选品弹窗（搜索、规格下拉、本地商品与主库商品同一套变体解析）。商品卡「加入组合」在无组合时先引导创建再自动带入选品。
- **覆盖防护**：保存一律使用 `saveProductBundle` 的 revision 乐观锁；保存成功只用返回结果更新本地对应组合，不再整表回拉，创建/改名/增删不会被慢回拉覆盖（e2e 断言增删改名期间列表请求数为 0）。初始加载保留请求序号守卫。
- **上限保留在 UI 层**：每账号 10 组合、每组 5 商品；后端 bundles 自身的明细/数量约束不变。
- 经验：选品弹窗 `<dialog>` 不可挂 `flex` 类；预选商品可能不在共享分页结果中，展示列表需并集已选项；分页接口异常时 rows 回退空数组。
