# RENDER-004 商品多图与完整场景输出

日期：2026-10-20。状态：实现与专项验证通过，真实模型视觉验收待完成。

## 用户要求与原因

商品不止一张图片，主图外的角度/细节图也应辅助生成；成品中不能在房间中央插入平面布局图，也不能出现侧边商品清单。截图显示模型把扁平布局条件图与文字清单作为成品的一部分，商品图仍仅使用主图。

## 实现

- 从商品 image_assets 图库补充图片，主图优先；只使用该商品的公共图片或当前变体图片，排除其他变体。按 URL 与图片内容去重，单款最多 4 个可用不同视角，主图占主要参考区域，辅助图补充侧面/背面/细节；不可读图片尝试其他图，无可用图时仍阻止调用生图。
- 不按照片数增加商品或家具。每款的所有角度合入同一编号参考块，依旧最多两张商品参考板加一张空间引导，不突破供应商输入限制。任务记录 images、usedImageCount、availableImageCount 和图片摘要，页面区分商品款数与照片张数。
- 新增无文字的立体空间引导图：保留真实房间轮廓与家具位置/旋转，将占地升成立体代理块，按鸟瞰/室内视角选投影；默认家具高度属于概念引导假设。原平面 PNG 仅保存作页面核对，不再作为生成输入。
- 正向提示要求满幅、连贯、同一透视的真实场景；明确禁止参考图、中央图板、悬浮图纸、清单、分栏、编号及拼贴。减少已选商品的重复名称清单，增加 negative_prompt 同向限制。空间引导仅负责结构，模型需用真实商品替换代理块。
- 新增 layoutGuideUrl，保存并展示实际用于生成的空间参考，与平面核对图分开；旧任务保留原数据，不冒充新版多图或新空间引导。

## 验证计划

前端构建、效果预览 UI mock；Java 商品多图像素、重复图/变体过滤、主图缺失后的辅助图回退、立体引导与平面图不同、两种视角不同、负向提示传输，以及原有生成/历史/幂等保护。文档链接与差异检查。

## 验收边界

本轮不自动提交新的收费生成或改写用户既有图片；本地结构引导不是精确 3D 模型，照片辅助与提示约束不能保证生成模型绝不画错。需要部署新版并重新生成验证实际视觉对应。独立外部图片链接仍需先入库，不能解码的图片会跳过并记录提示；主图也不可用且无其他图时会报错。
