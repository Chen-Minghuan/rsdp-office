# LAYOUT-011 按空间用途分流排版

状态：进行中
更新日期：2026-10-17
负责人：Codex
关联：产品需求第 4、6 节、LAYOUT-001、LAYOUT-010

## 背景与目标

职员办公区需要多排、面对面、背靠背和中央通道等工位排布；会议室的核心对象是一张会议桌，周围要保留拉椅和通行空间。两者不能共用按空间面积复制家具的默认算法。

## 当前流程

1. 根据空间用途选择排版上下文。
2. 会议室默认选择会议与洽谈目录中的长方形会议桌；开放办公区保留职员桌目录和产品样式。
3. 会议室使用“单桌居中”方案，会议桌外围默认预留 1200mm；职员桌继续使用原有自动多排和专用排布模板。
4. 椅子、显示设备和其他附属家具仍通过单位模块目录手动添加，不能被自动排版误认为会议桌数量。
5. 已有旧会议室多排草稿显示待应用状态；用户点击“应用单桌居中”后才替换旧布局，避免静默清空编辑。

## 验收标准

- [x] `MEETING_ROOM` 进入排版时默认选中会议桌，而不是职员直线桌。
- [x] 会议桌自动方案最多生成一张居中桌，且外围通行预留参与可放入检查。
- [x] 会议室侧栏不显示职员桌专用样式，明确提示会议室与开放办公区的排布差异。
- [x] 应用会议方案保存 `layoutContext=meeting`，旧布局可通过显式应用替换。
- [ ] 会议桌座席数量、椅子联动、屏幕/白板和门口通道校验接入服务端确认。

## 实施与验证

- 新增 `planMeetingFurniture` 安全规划器；会议室不再调用职员桌多排填充算法。
- `DesignLayoutSidebar` 按 `zoneType` 设置默认模块、样式和按钮文案。
- `createTemplateFurniture` 保存排版上下文并使用对应规划器。
- `pnpm test:auto-layout` 覆盖单桌居中、中心坐标和通行预留失败。
- `pnpm build` 通过；保留项目既有重复导入和 Node 依赖警告。
- `PLAYWRIGHT_EXECUTABLE_PATH=... pnpm e2e:meeting-layout` 通过；模拟会议室默认会议桌、单桌居中、旧按钮隐藏和 `layoutContext=meeting` 保存。
- 既有家具模块浏览器回归通过；完整真实数据库和用户图纸验收仍待补充。

## 当前限制

会议桌的自动方案只负责桌体占地，暂不自动生成椅子或会议设备；正式方案确认还需要服务端按空间用途、门口、通行宽度和座席数量重新核验。
