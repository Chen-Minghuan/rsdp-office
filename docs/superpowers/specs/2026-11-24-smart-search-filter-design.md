# 智能搜索和筛选器设计

日期：2026-11-24
分支：`feature/smart-search-filter`
状态：界面样式已确认，设计文档待审阅；尚未开始实现

## 1. 背景与当前证据

商品库当前已有名称/编码搜索、`categoryPath` 分类、`colorPrimaryName` 主色和在售状态筛选，页面右侧为自选组合与收藏夹。本需求在不改变右侧业务的前提下，增加统一的“全部筛选”入口和双栏筛选弹层。

本设计使用 Office 当前配置的 RSDP 测试主库 `https://rsdp-test.rooom.vip` 做只读调查，不将结果当作生产数据：

- 当前可见商品 185 个，全部在售；商品详情读取成功 185/185。
- 当前共有 185 条规格，每个商品 1 条，规格全部在售。
- `productLevel`、`categoryCode/categoryPath`、`colorPrimaryName` 覆盖 185/185。
- `productLevel` 全部为 B；`categoryCode/categoryPath` 全部为 OF/办公家具。
- `sceneTags`、`materialTags`、`fabricTags`、`sixDimTags`、`keySpecs` 均为 0/185。
- 规格 `materialText` 全部为 PB；`colorCode/colorText`、`materialCode`、`sizeCode/sizeText` 均为空。
- 182/185 个规格有有效毫米宽、深，181/185 有有效高度。
- 测试主库当前未提供 Office 新版 `catalog-page` 接口，Office 必须保留 `/products` 列表兼容路径。

参考图片只决定交互和视觉方向，不作为分类值依据。

## 2. 目标与范围

### 2.1 本期目标

1. 在商品库搜索栏右侧增加“全部筛选”入口，初始页面不显示弹层或已选条件。
2. 桌面端使用居中双栏弹层，手机端使用全屏双栏筛选。
3. 支持产品等级、空间类型、产品分类、材质、颜色、尺寸、桌脚、收纳八类条件。
4. 弹层内暂存选择，确定后统一应用；取消不改变原筛选。
5. 在 Office 后端对全部授权商品完成筛选和选项统计后再分页，不只处理当前页。
6. 保留现有搜索、在售状态、公共库、本地商品、收藏、自选组合和分页行为。

### 2.2 非目标

- 不做自然语言搜索、以图搜图、AI 推荐或搜索广告。
- 不向 RSDP 回写分类，不新增主库字段，不执行商品或字典数据补录。
- 不把 19 个“单人位/双人位/四人位/延伸位”并入桌类。
- 不把 2 个钢脚配件和 1 个屏风硬归入桌、柜、椅、沙发。
- 不修改右侧自选组合、收藏夹及其接口。
- 不在首版增加独立深度、高度筛选组，不把尺寸原文当作结构化尺寸。
- 不将测试库的数量硬编码为生产规则或验收预期。

## 3. 方案选择

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| Office 后端读取授权目录、派生并筛选后分页 | 不改 RSDP 契约；统一处理旧接口；适合当前 185 个商品 | 详情和规格读取需要缓存；商品量增大后需下推 | 本期采用 |
| RSDP 主库直接提供全部筛选与聚合 | 性能和扩展性更好 | 需要跨仓库接口、迁移与发布协调 | 数据规模增大后的演进方向 |
| 前端只对当前页派生和筛选 | 改动表面较少 | 会漏掉其他页商品，统计和分页错误 | 排除 |

首版不要求 RSDP 同步发布。Office 使用现有列表、详情和规格接口完成闭环，后续数据规模或调用量明显增长时，再把过滤与聚合下推到 RSDP。

## 4. 已确认的视觉与交互

### 4.1 未打开筛选器的主界面

- “全部筛选”位于搜索栏右侧、刷新按钮左侧。
- 顶部保留搜索商品、产品分类、商品主色、在售状态。
- 初始状态没有已选标签和弹层，商品网格、右侧组合与收藏保持原布局。
- 产品分类下拉使用本设计的派生产品类型；商品主色下拉使用本设计的具体颜色。两者与弹层共享同一份已应用筛选状态。

### 4.2 桌面端弹层

- 居中显示，参考宽度约 1040px，最大高度约视口的 82%。
- 标题为“全部筛选”，右上角关闭。
- 左侧为八类导航，显示各类已选数量；右侧只显示当前分类选项。
- 选项以三列卡片排列，选中项使用现有紫色边框和浅紫背景。
- 底部固定“清空选择 / 取消 / 确定”，确定按钮显示草稿已选总数。
- 遮罩覆盖商品区，背景不响应业务操作。

### 4.3 手机端弹层

- 全屏显示，不使用居中小弹窗。
- 左侧窄分类导航，右侧两列选项；左右内容区可独立滚动。
- 底部“清空选择 / 确定”在 390×844 视口内完整固定显示，不遮挡选项。
- 适配窄屏长文字、触控区域和安全区。

### 4.4 草稿与应用语义

维护两份状态：

- `appliedFilters`：当前商品列表实际使用的条件。
- `draftFilters`：弹层内正在编辑的条件。

规则：

1. 打开弹层时复制 `appliedFilters` 到 `draftFilters`。
2. 点击选项只修改 `draftFilters`，不请求商品列表。
3. 关闭或取消放弃草稿，原列表和条件不变。
4. “清空选择”只清空草稿，确定后才生效。
5. 确定后请求第一页；只有请求成功才替换 `appliedFilters`、列表和已选标签。
6. 请求失败时保留原已应用条件和列表，弹层草稿保留并显示可重试错误。
7. 快捷下拉修改使用已应用状态；下次打开弹层时同步到草稿。
8. 所有请求使用递增序号或等效保护，过期响应不得覆盖新状态。

### 4.5 条件组合

- 同一分组多选按 OR，例如颜色为蜜芽胡桃或雅士白。
- 不同分组按 AND，例如 B级 + 职员空间 + 桌类 + 1.4m。
- 材质与尺寸是规格条件，必须由同一个规格同时满足。
- 产品可因任一规格满足全部规格条件而进入结果。
- 颜色和桌脚是多标签，选项数量允许重叠。
- 空间和收纳是单值派生，选项数量不重叠。
- 产品类型首版只提供桌、柜、椅、沙发四个选项；未归类商品在未选择产品类型时仍可见，选择任一类型后不进入结果。

## 5. 字段与派生规则

`productLevel`、`materialText`、`colorPrimaryName`、`dimensions` 是直接读取字段。`spaceType`、`productType`、`colorNames`、`legTypes`、`storageType` 是 Office 计算字段，不回写 RSDP。

### 5.1 产品等级 `productLevel`

来源：商品列表/主档 `productLevel`。首版以主档等级为准，规格级同名字段不覆盖，避免同一商品出现多个等级。

固定选项：`S`、`A`、`B`、`C`。当前测试快照为 S=0、A=0、B=185、C=0。

### 5.2 空间类型 `spaceType`

来源：仅使用 `productName`，单值映射；不使用当前全空的 `sceneTags`。名称同时命中多个空间时按表格顺序取第一个。

| 编码 | 显示名 | 名称包含 |
|---|---|---|
| `STAFF` | 职员空间 | 职员台 |
| `MANAGER` | 主管空间 | 主管台 |
| `SENIOR_MANAGER` | 高管空间 | 高管台 |
| `PRESIDENT` | 总裁空间 | 总裁台 |
| `MEETING` | 会议空间 | 会议台 |
| `NEGOTIATION` | 洽谈空间 | 洽谈台 |
| `RECEPTION` | 接待空间 | 前台 |
| `PANTRY` | 茶水空间 | 茶台、茶水柜 |
| `UNSPECIFIED` | 未说明 | 以上均未命中 |

当前测试快照依次为 61、24、13、3、15、3、1、9、56，合计 185。

### 5.3 产品分类 `productType`

来源：仅使用 `productName`，单值映射；不使用当前只有 OF/办公家具的 `categoryPath` 代替。识别优先级为沙发→椅→台/桌/茶几→柜，避免多关键词商品被重复归类。

| 编码 | 显示名 | 名称包含 |
|---|---|---|
| `DESK` | 桌类 | 台、桌、茶几 |
| `CABINET` | 柜类 | 柜 |
| `CHAIR` | 椅类 | 椅 |
| `SOFA` | 沙发类 | 沙发 |
| `UNCLASSIFIED` | 未归类 | 其他，不作为首版筛选项 |

当前测试快照为桌类 131、柜类 31、椅类 1、沙发类 0、未归类 22。19 个位类、2 个钢脚配件和 1 个屏风保持未归类。名称同时含“单人位”等词和“职员台”的商品仍因“台”归为桌类；只有不含台/桌/茶几的 19 个位类不并入。

### 5.4 材质 `materialText`

来源：`variants[].materialText`，当前只显示 PB，不翻译成“板式”。后续出现其他真实原文时按原文扩展。

### 5.5 颜色 `colorNames`

来源：`colorPrimaryName`，按 `+` 拆分、去空格、按商品去重，一个商品可有多个颜色。

首版只将以下已核实颜色词生成选项：雅士白、蜜芽胡桃、液态银、纳柯、暮山黑橡、月影胡桃、海鸥灰、爱马仕橙、天使白、灰绿色(扪布)、高级灰、棕色、灰色。

灯带、烧水壶、乌金石茶盘、双电机升降台、独立副柜、独立升降台、玛德德岩板等不生成颜色选项。哑黑铝框、深灰银钢脚等混合词不擅自拆成新颜色；商品仍可由其他明确颜色词匹配。

主要测试快照：雅士白 108、蜜芽胡桃 106、液态银 49、纳柯 48、暮山黑橡 13、月影胡桃 10、海鸥灰 10、爱马仕橙 7，其余明确颜色各 1。颜色数量可重叠。

### 5.6 尺寸 `widthMm`

来源：`variants[].dimensions.w`，复用现有尺寸解析并统一换算为毫米，要求结果为有限正数；不使用 `sizeCode/sizeText`。无法可靠解析或换算的进入“未标注”，不猜测单位。

- 首版只按宽度生成选项，显示为米并去除多余尾零，例如 1200→1.2m。
- 深、高继续保留在商品规格中，但不生成独立筛选组。
- 无有效宽度的商品归为“未标注”；当前测试快照为 3 个。
- 当前测试快照：1.2m=21、1.4m=26、1.5m=11、1.6m=14，全部共有 23 种有效宽度。

### 5.7 桌脚 `legTypes`

来源：`productName + rspu.description`，多标签映射：

- 命中“钢脚”→ `STEEL` / 钢脚。
- 命中“支撑柜”→ `SUPPORT_CABINET` / 支撑柜。
- 都未命中→ `UNSPECIFIED` / 未说明。

当前测试快照为钢脚 40、支撑柜 32、未说明 135；其中 22 个商品同时具有两个标签。

### 5.8 收纳 `storageType`

来源：`productName + rspu.description`，每个商品只得到一个主收纳配置。先查商品名称，再查描述；每个来源内按以下顺序取第一个命中：

1. `MOBILE_SMALL_CABINET` / 活动小柜
2. `LONG_SIDE_CABINET` / 长副柜
3. `HIGH_CABINET` / 高柜
4. `BACK_CABINET` / 背柜
5. `SUPPORT_CABINET` / 支撑柜
6. `SIDE_CABINET` / 副柜
7. `DRAWER` / 抽屉
8. `UNSPECIFIED` / 未说明

当前测试快照依次为 2、3、1、1、32、27、7、112，合计 185。该优先级只决定首版主配置，不回写或删除商品的其他真实配置描述。

## 6. 选项数量与结果统计

为保持数量稳定，首版采用统一统计口径：

1. 先按当前目录授权范围、名称/编码搜索和在售状态得到基础集合。
2. 八类选项数量基于该基础集合统计，不随八类条件的选择继续缩减。
3. 修改搜索、目录范围或在售状态后重新统计并清理已不存在的选项。
4. 商品列表 `total` 是在基础集合上再应用八类条件后的数量。
5. `catalogTotal`、`activeTotal` 继续沿用当前目录统计语义。

这样多选时选项不会频繁跳动；收纳计数始终互斥，颜色和桌脚计数按实际多标签计算。

## 7. Office 后端设计

### 7.1 职责划分

- `ProductImportController`：接收协议参数、校验分页和筛选输入。
- `ProductQueryService`：确定授权视图，协调基础集合、派生、过滤、统计和分页。
- 独立商品筛选派生模块：以商品主档、描述和规格为输入，输出可测试的筛选属性，不写数据库、不处理 HTTP。
- `RsdpCatalogGateway`：复用现有主库列表、详情、规格读取和兼容回退，不在控制器中拼接分类规则。

派生模块必须可以独立测试，输入输出明确，不依赖 Vue 或 Spring MVC。

### 7.2 接口

扩展现有 `GET /api/v1/products/page`，保留 `managed/page/size/search/status`，新增可选数组参数：

- `levels`
- `spaceTypes`
- `productTypes`
- `materials`
- `colors`
- `widthsMm`
- `legTypes`
- `storageTypes`

数组统一使用同名重复参数，例如 `levels=B&levels=A&colors=蜜芽胡桃&colors=雅士白`；前后端分别 URL 编码。派生枚举使用稳定编码，颜色使用归一后的真实颜色词，宽度使用正整数毫米。

每个筛选数组最多 50 项，颜色文本最长 64 字符，材质文本最长 128 字符，宽度为 1–100000 的整数毫米。校验失败返回业务参数错误，不静默接受未知枚举、非法尺寸或超限列表。

响应在现有 `rows/total/catalogTotal/activeTotal/page/size` 上增加 `facets`：

```json
{
  "levels": [{"code":"B","label":"B","count":185,"disabled":false}],
  "spaceTypes": [{"code":"STAFF","label":"职员空间","count":61,"disabled":false}],
  "widthsMm": [{"code":"1200","label":"1.2m","count":21,"disabled":false}]
}
```

实际响应包含全部八类。`disabled` 用于数量为 0 或当前不可用的选项，前端不能只根据本地写死的数据决定禁用状态。

### 7.3 缓存与授权

- 原始商品和规格读取复用现有缓存及最多 8 并发。
- 派生快照至少按目录视图和工厂/授权范围隔离，不能跨工作区复用不可见商品。
- 搜索和状态条件在授权集合之后执行，不作为共享快照的缓存键。
- 公共库开关、目录切换和手动刷新必须使相关缓存失效。
- 弹层内的选项点击不触发全量回源；只有确定、快捷筛选或手动刷新才查询。
- 若 RSDP 新版接口可用，保持现有兼容回退；不能因测试库没有 `catalog-page` 而绕开旧列表。

## 8. 前端设计

建议新增：

- `ProductAdvancedFilterDialog.vue`：双栏弹层、草稿、分类导航、移动端布局、确定/取消/清空。
- `productFilter.ts`：筛选状态、选项标签、已选数量、查询参数转换和已选标签。
- 商品库页只负责快捷条件、已应用状态、列表加载和弹层集成。
- `useOfficeApi.ts` 与商品类型定义补充筛选参数和 `facets` 类型。

交互要求：

- 弹层使用 `role=dialog`、`aria-modal=true` 和可访问标题。
- 打开后焦点进入弹层，Tab 不离开弹层，Esc 取消，关闭后焦点返回“全部筛选”。
- 左侧分类切换保留各分类草稿，已选数量为草稿统计。
- 应用筛选后显示已选标签，单个移除或全部清空后立即重新查询第一页。
- 加载中不伪造 0 件；无结果显示“没有匹配商品”；请求失败提供重试。
- 目录切换后移除不可见选项，避免用旧条件筛选新目录。

右侧收藏、组合、图片预览和详情入口继续复用现有组件，不在本需求中重写。

## 9. 错误与边界行为

| 场景 | 预期行为 |
|---|---|
| 取消或关闭弹层 | 放弃草稿，原条件与列表不变 |
| 确定后请求失败 | 保留旧条件和列表，草稿可重试并展示错误 |
| 筛选无结果 | 显示空结果和清空入口，不报错 |
| 商品缺少尺寸 | 只能进入“未标注”，不得按 0mm 处理 |
| 商品缺少名称/描述 | 空间、产品类型、桌脚、收纳按未说明或未归类 |
| 颜色只有混合配置词 | 不生成猜测颜色，保留其他真实属性 |
| 一个商品多个规格 | 所有规格条件必须由同一个规格满足 |
| 目录切换或权限变化 | 清理不可见条件和缓存，重新统计 |
| 旧响应晚于新响应 | 丢弃旧响应，不覆盖当前条件与列表 |

## 10. 验收标准

### 10.1 界面与交互

- 未打开筛选器的主界面与已确认渲染一致，入口位于搜索栏右侧、刷新左侧。
- 桌面端双栏弹层、手机端全屏双栏与已确认渲染一致。
- 左右分类切换、选项多选、数量徽标、清空、取消、确定和已选标签行为符合本设计。
- 390×844 视口底部按钮完整可见，桌面和移动布局无横向溢出。
- 键盘、焦点、Esc、加载、失败、空结果行为可验证。

### 10.2 数据与筛选

- 等级、材质、颜色、尺寸使用直接字段；派生规则与第 5 节逐项一致。
- 19 个位类不并入桌类，2 个钢脚配件和 1 个屏风不硬归类。
- 收纳按主配置计数，测试快照合计 185 且不重复。
- 后端先筛选统计再分页，切换筛选回到第一页。
- 组内 OR、组间 AND、同规格匹配和过期响应保护通过测试。
- 只读核对测试库时，等级 B=185、桌类=131、空间与收纳数量符合第 5 节；这些数值只作为当前测试快照，不作为生产断言。

- `frontend/` 下 `pnpm build`
- 商品筛选专项 UI 测试及 `pnpm e2e:workflows`
- 收藏、组合、公共库、分页和移动端相关回归
- RSDP 测试库只读覆盖与抽样核对，不写入业务数据
- `git diff --check`

UI mock、真实接口、真实数据库和业务验收分别记录。当前没有独立 lint/typecheck，不将构建描述为这些检查。

## 11. 风险与后续演进

- 名称/描述派生依赖当前商品资料质量，必须通过“未说明/未归类”暴露不确定性；后续主库提供正式字段时优先替换。
- 颜色词表需要随真实数据复核，未知词不能自动变成颜色。
- 全量详情与规格读取有性能成本，必须测量缓存命中和回源耗时；数据量增长后下推 RSDP。
- 当前商品全为 B、PB、办公家具，部分条件暂时没有区分度，但实现不得伪造其他值。
- 首版尺寸仅按宽度筛选，避免把不同品类的宽、深、高混为一个尺寸概念。
- 桌面与手机是同一状态的不同呈现，不能分别维护两套筛选条件。
